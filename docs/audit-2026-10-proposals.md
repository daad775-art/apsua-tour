# Изменения по аудиту, требующие согласования

Аудит от 30 октября 2026 года. Всё в этом документе — предложения. Ничего из них не применяется к рабочему сайту автоматически. Предложение показа окна установки приложения владелец оставил как есть, поэтому здесь его нет.

## 1. Индексы таблицы `records` (эта ветка)

**Что меняется.** Миграция `drizzle/0001_records_indexes.sql` добавляет три индекса: `(kind, owner, created)`, `(owner, created)` и `(kind, status, created)`. Индексы описаны также в `db/schema.ts`, и `npm run db:generate` больше не будет предлагать их заново. Строки таблиц миграция не трогает. `CREATE INDEX IF NOT EXISTS` можно безопасно запускать повторно.

**Зачем.** В `records` хранятся заявки, профили, сессии, загрузки, push-подписки, напоминания и публичные ID. Без индексов почти каждый запрос по `kind` или `owner` читает таблицу целиком, а D1 берёт плату за каждую прочитанную строку. Замер на 60 000 строках (node:sqlite, те же запросы, что в `lib/site-api.ts`):

| Запрос | Без индексов | С индексами |
| --- | --- | --- |
| профили авторов (`kind='profile' AND owner IN …`) | 5,3 мс, полное чтение | 0,03 мс |
| избранное пользователя | 4,8 мс, полное чтение | < 0,01 мс |
| «Мои заявки» | 5,9 мс, полное чтение + сортировка | 0,01 мс |
| лимит загрузок за сутки | 5,2 мс, полное чтение | < 0,01 мс |
| напоминания о поездках | 3,8 мс, полное чтение | 1,8 мс |
| список заявок для сотрудников по статусу | 6,6 мс, полное чтение | 0,07 мс |

**Цена.** Три индекса добавляют место (примерно по ширине ключей на каждую строку) и немного замедляют вставку. При нагрузке сайта это незаметно.

**Как проверить до публикации.**
1. Сделать копию рабочей базы: `wrangler d1 export <база> --remote --output=backup.sql`. Это только чтение.
2. Развернуть копию локально и применить миграцию: `wrangler d1 execute <база> --local --file=backup.sql`, затем `--file=drizzle/0001_records_indexes.sql`.
3. Сравнить число строк во всех таблицах до и после и выполнить `EXPLAIN QUERY PLAN` для запросов из таблицы выше.
4. Тест `tests/d1-indexes.mjs` делает то же на синтетических данных.

**Откат.** `DROP INDEX records_kind_owner_created_idx; DROP INDEX records_owner_created_idx; DROP INDEX records_kind_status_created_idx;` Данные при этом не меняются.

## 2. Тарифная миграция в `GET /api/state`

**Сейчас.** Каждый `GET /api/state` проверяет `content.transfer.tariffRevision !== 42`. Если номер не совпадает, обработчик переписывает классы и тарифы трансфера из `lib/transfer-rates.json` и сохраняет каталог. Это запись в базу внутри запроса на чтение, хотя срабатывает она один раз.

**Предложение.**
1. Вынести переписывание в функцию `migrateTransferTariffs(env)`.
2. Вызывать её из `scheduled()` (cron уже настроен на каждые 15 минут) и перед сохранением `/api/content`.
3. В `GET /api/state` оставить только чтение. Если ревизия меньше 42, отдавать тарифы из `transfer-rates.json` без записи в базу, чтобы цены не устаревали до первого запуска cron.
4. Убирать ветку из `GET`, только когда в рабочем каталоге подтверждено `tariffRevision: 42`. Проверка — выгрузка каталога из админки.

**Последствия.** Текущие тарифы и порядок их обновления сохраняются. Новая тарифная ревизия (43 и далее) будет применяться через cron, а не первым посетителем.

## 3. Обычные адреса вместо `#/…`

**Сейчас.** Страницы живут в адресах вида `/#/excursions/<id>`. Сервер уже отдаёт оболочку на `/catalog`, `/transfer`, `/map`, `/journal`, `/tour/<id>`, `/account`, `/administrator`. Клиент переводит такой путь в hash (`route()`, `history.replaceState`). Поэтому прямые ссылки работают, но в адресной строке остаётся `#`. В этой ветке сервер уже отдаёт для `/tour/<id>` собственный заголовок, описание и canonical, а `sitemap.xml` перечисляет эти пути.

**Предложение (отдельным PR).**
1. Ввести одну функцию `go(path)` вместо записи в `location.hash` и перевести ссылки `href="#/…"` на `href="/…"`, перехватывая клики по своим ссылкам.
2. Обрабатывать `popstate` вместо `hashchange`. «Назад» и «вперёд» продолжают работать: каждый переход кладёт запись через `history.pushState`.
3. **Совместимость старых ссылок.** При загрузке `/#/excursions/x` переводить на `/tour/x` через `replaceState`, без лишней записи в истории. Старые ссылки из мессенджеров и закладок продолжают открываться.
4. **Прямое открытие и обновление.** Сервер должен отдавать оболочку на все клиентские пути. Список в `build/sites-worker.ts` расширяется до полного перечня маршрутов (`/diary`, `/reviews`, `/orders`, `/faq` и т. д.).
5. Сохранение прокрутки и защита несохранённых правок в админке (`adminLastHash`, `apsuaAdminDirty`) сейчас завязаны на hash. Их нужно перевести на `popstate` в том же PR и покрыть тестами.

**Последствия.** Страницы экскурсий получают чистые адреса для поиска и шаринга. Изменение затрагивает навигацию по всему сайту, поэтому нужны отдельная проверка всех экранов и тесты.

## 4. Страница экскурсии: вторая кнопка «назад» и цена

**Сейчас (телефон).** Над заголовком стоят две кнопки возврата: круглая со стрелкой и «Назад». Цены на первом экране нет, сразу после названия идёт строка «Условия подтвердит организатор».

**Предложение.** Оставить одну кнопку — круглую (как в шапке приложений) или «Назад» справа. Под названием показывать «от … ₽» из того же расчёта, что и в бронировании (`tourOffer`). Если цена зависит от даты и города, писать «от» с минимальной ценой сезона.

**Последствия.** Освобождается примерно 70 px первого экрана, цена видна без прокрутки. Это изменение вида, поэтому оно ждёт решения владельца.

## 5. Запрет показа сайта во фрейме

В этой ветке HTML отдаётся с `Content-Security-Policy: object-src 'none'; base-uri 'self'`. Защиту от встраивания (`frame-ancestors`) я не включал: предпросмотр хостинга может показывать сайт во фрейме, а проверить это из среды аудита нельзя. Предложение: открыть опубликованный сайт и посмотреть заголовки ответа. Если платформа не ставит `X-Frame-Options`, добавить `frame-ancestors 'self'` и разрешить домен предпросмотра, если он нужен.
