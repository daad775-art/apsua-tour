# Telegram Login без чата с ботом

Текущий интерфейс использует официальный SDK
`https://oauth.telegram.org/js/telegram-login.js?6`, `Telegram.Login.auth()`.
Кнопка открывает окно Telegram, а не `t.me` и не чат с ботом.
После разрешения и серверной проверки сайт автоматически входит в существующий
аккаунт `tg:<id>`. Запрашивается только `profile`: без `phone` и `write`.
Telegram сам решает, нужны ли дополнительная проверка, вход в аккаунт или подтверждение
в приложении. Сайт не может гарантировать отсутствие этих проверок.

Одноразовая настройка владельцем в мини-приложении @BotFather:
выбрать @ApsuaturBot → Login Widget → Allowed URLs, добавить origin опубликованного сайта.
В этом сценарии используется публичный Client ID (Bot ID из серверного токена),
Client Secret не нужен: код авторизации не обменивается, SDK возвращает подписанный ID token.
Бот остаётся техническим представлением сервиса в Telegram; вести с ним чат не требуется.

API: `POST /api/telegram-oidc/start`, `POST /api/telegram-oidc/finish`.
Пять минут, одноразовый nonce, отдельное HttpOnly/Secure cookie с хешированным доказательством
браузера, тот же Origin, ограничение числа запросов. Сервер проверяет RS256/ES256-подпись по JWKS
Telegram, `iss`, `aud`, `nonce`, `sub`, `iat`, `exp`, числовой Telegram ID и атомарно
погашает запрос до создания сессии. JWT не записывается в базу или журнал.
Поддерживаются стандартный RS256 и ES256.

Прежние bot-webhook endpoints оставлены для уже начатых запросов на время их истечения;
публичный интерфейс их больше не вызывает. Ранее выданные сессии и вход ChatGPT администратора
сохранены. Тесты: `tests/telegram-oidc.mjs`, `tests/telegram-login-ui.mjs`.

Документация: https://core.telegram.org/bots/telegram-login


## Совместимость профиля и возврат из Telegram (14.6)

`sub` — обязательная OIDC-идентичность, `id` — необязательное поле профиля.
Числовой `id` и его десятичная строка нормализуются одинаково. При отсутствии `id`
используется отдельное пространство `tg:oidc:<hash>`, не догадка о Bot API ID.
Приватная запись `tg-subject` фиксирует связь subject/client с владельцем при первом
проверенном входе. Имя и username никогда не используются для слияния аккаунтов.
Повторное открытие формы сохраняет ещё действующий nonce, чтобы возврат из приложения
не ломался из-за перерисовки страницы. Клиент проверяет сохранение сессии через `/api/state`.
Диагностика отказа пишет только название этапа (`nonce`, `signature`, `subject` и т. п.),
без JWT, имён, идентификаторов, cookie и других пользовательских данных.

На компьютере официальное окно Telegram предоставляет «Продолжить с Telegram» и
«Или войдите по номеру телефона». Сайт не может использовать сессию Telegram Web
с другого origin или принудительно добавлять собственные методы в окно Telegram.


## Сбой получения публичных ключей (14.7)

Продакшен-журнал показал отказ на этапе `keys`. Если HTTPS-загрузка официального JWKS
недоступна, сервер использует включённые в исходники публичные RSA/EC ключи, полученные
2026-10-24 из `https://oauth.telegram.org/.well-known/jwks.json`.
SHA-256 исходного ответа: `ff43610c7cca372000fd6a9eed14695e8af9d70f65aabc00fdf5694588fe2e48`.
Это публичные ключи проверки; секретов и приватных ключей в исходниках нет.

При доступном JWKS используется ответ Telegram, не локальная копия. После сбоя повторная
попытка загрузки производится через минуту. Неизвестный `kid` повторно запрашивает JWKS
и отклоняется, если нет подходящего ключа. Подпись, issuer, audience, nonce, срок и cookie
по-прежнему обязательны. При ротации Telegram и одновременно недоступном JWKS нужно
обновить снимок публичных ключей: новые неизвестные ключи намеренно не принимаются.

Тест `tests/telegram-key-cache.mjs` проверяет отказ сети, HTTP 403, не-JSON, обе подписи,
неизвестный ключ и отсутствие подмены ключей из клиентского запроса.


## Обновление состояния без перезагрузки (14.8)

Анонимный переход по ссылке кабинета открывает компактный dialog поверх текущей страницы.
Кнопка в бронировании сохраняет форму. После подтверждения `/api/state` передаёт профиль,
права и приватные списки в состояние приложения; шапка и плашка заказов обновляются сразу.
Функция не вызывает `location.reload()` и не открывает редактор профиля.

Если вход был начат с отдельной страницы кабинета, возвращаемся на последнюю публичную
страницу этого браузерного сеанса (вместе с фильтрами и прокруткой); иначе — на главную.
Возврат ограничен внутренними маршрутами сайта, админка/кабинет/внешние URL исключены.
Публичная форма на исходной странице не перерисовывается и сохраняет введённые значения.

Короткий маркер начатого входа в sessionStorage содержит только срок и публичный маршрут,
не JWT и не cookie. Возврат из Telegram, pageshow и focus проверяют уже выданную сервером
сессию; повторная отрисовка не теряет callback. Фоновое обновление не перезагружает страницу
во время входа, а устаревший ответ /api/state не может перезаписать новый профиль гостем.
При ошибке/отказе/истечении пяти минут кнопка снова доступна.
# Запасной вход в Telegram Web (14.9)

На компьютерах с мышью под основной кнопкой есть ссылка «Через Telegram Web».
На телефонах основной сценарий остаётся прежним. Web-ссылка ведёт прямо в официальный
Web K: `https://web.telegram.org/k/#?tgaddr=<encoded tg://resolve?domain=...&start=login_...>`.
Это формат, который обрабатывает исходный код Web K (`morethanwords/tweb`,
`src/index.ts`, `src/lib/internalLinkProcessor.ts`, `startParam: link.start`).
Если посетитель ещё не вошёл в Telegram Web, авторизация самого Telegram выполняется
его средствами; сайт не получает телефон или пароль Telegram.

Используется существующий защищённый bot webhook. Сервер создаёт короткоживущий запрос
с `mode: web`; бот показывает только название сайта и «Авторизоваться»/«Отклонить».
Код сверки в этом режиме не выводится. Нужны исходное браузерное cookie-доказательство,
явное подтверждение именно связанного Telegram-пользователя и одноразовое погашение.
Сайт проверяет статус и завершает вход автоматически в исходной вкладке, сохраняя маршрут.
Основной официальный OIDC-вход и ранее начатые legacy-запросы сохранены.

Тесты: `tests/telegram-web.mjs`, `tests/telegram-login-ui.mjs`.


### Единая кнопка (15.0)
Один элемент «Войти через Telegram» на всех устройствах. При наличии точного указателя и hover кнопка заранее готовит Web-ссылку и открывает её синхронно по клику. На сенсорных устройствах используется официальный Login SDK. Отдельной ссылки выбора способа нет.
