# Вход через установленное приложение Telegram

Кнопка открывает `https://t.me/ApsuaturBot?start=login_<nonce>`.
Пользователь нажимает «Начать», сверяет шестизначный код с сайтом и подтверждает вход.
После возвращения в исходный браузер сайт предлагает «Войти как …».
Телефон и SMS сайт не запрашивает; если Telegram не установлен или пользователь вышел из него,
авторизация самого приложения зависит от Telegram.

Требуются runtime-секреты `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`.
Webhook бота: `/api/telegram-bot-webhook`, Telegram `secret_token` должен совпадать со вторым секретом.
Доставляются только `message` и `callback_query`. Настройка `/setdomain` для этого сценария не нужна.
Не перезаписывайте чужой существующий webhook без согласования: у бота может быть только один получатель.

Запрос живёт пять минут в приватной записи `tg-login`. Публичный nonce не даёт права войти:
нужны исходный HttpOnly/Secure cookie с отдельным случайным доказательством, подтверждение
именно того аккаунта, который начал вход, и финальное согласие в браузере. Доказательство
хранится в D1 в виде SHA-256. Повторное завершение отклоняется атомарным изменением статуса.
Идентификатор пользователя остаётся `tg:<id>`, прежние заявки сохраняют владельца.
Обычный ChatGPT-вход администратора и существующие Telegram-сессии сохранены.

API браузера: `POST /api/telegram-login/start`, `GET /api/telegram-login/status`,
`POST /api/telegram-login/finish`. Мутации требуют тот же Origin. Сервер ограничивает создание
запросов десятью в минуту на хеш IP, старые запросы удаляются при следующем создании.
Не публикуйте nonce или код и не подтверждайте чужие ссылки.

Проверка: `node tests/telegram-app.mjs` — cookie, Origin, секрет webhook, неверный пользователь,
явное согласие, сессия, срок, отказ, повторное использование и лимиты. Реальные пользователи
и устройства в тесте не затрагиваются.
