# Автопарк и будущая диспетчерская интеграция

Каталог `content.fleet` — редакционные сведения о транспорте, не календарь доступности. Администратор редактирует его вручную и публикует кнопкой «Сохранить». Общее оформление сайта сохранено от версии 124, до отменённого редизайна.

## Каталог

`fleet.vehicles[]`: `id`, `name`, `type` (`sedan`, `minivan`, `minibus`, `bus`, `suv`, `offroad`), `capacity`, `luggage`, `features[]`, `photos[]`, `transfer`, `excursion`, `individual`, `group`, `hidden`, `example`, `transferClassIds[]`.

Пустая вместимость означает «уточняется», а не подтверждённую возможность перевезти любое число гостей. Пример (`example: true`) нельзя выбрать в заявке. Первая фотография — обложка. Номера машин и контакты водителей в публичном каталоге не хранятся.

`tour.vehicleIds[]` ограничивает список транспорта маршрута. Пустой список означает все совместимые экскурсионные автомобили. `transferClassIds[]` — устаревшее поле: с сборки 166 у трансфера только два формата (`individual`, `group`), и классы автомобилей на подбор транспорта не влияют. Сохранённые значения не удаляются. Дополнительно проверяются индивидуальный/групповой режим и известная вместимость.

## Пожелание туриста

В существующей отправке `/api/list` поле `preferredVehicleId` необязательно и разрешено только для индивидуальной поездки. Сервер проверяет ID по собственному каталогу и сохраняет снимок `preferredVehicle: {id, name, type}`. Это пожелание, оно не меняет цену и не подтверждает наличие машины.

Формат реального API диспетчерской системы ещё не предоставлен. Внешняя передача не подключена. Нового публичного метода назначения автомобиля и кнопок назначения в админке нет.

## Назначение с диспетчерского сервера

После разработки авторизованного адаптера в приватной записи заказа ожидается:

```json
{
  "assignedVehicle": {
    "id": "stable-dispatch-vehicle-id",
    "title": "Модель и обозначение автомобиля",
    "registration": "Госномер",
    "photo": "https://example.org/vehicle.jpg",
    "driver": {"name": "Имя водителя", "phone": "+79400000000"},
    "assignedAt": "2026-10-16T15:00:00+03:00"
  }
}
```

Поля кроме названия необязательны. Интерфейс также понимает `name` или `model` вместо `title`. Диспетчерский адаптер должен записывать данные только в принадлежащий туристу заказ, обновлять его `updated` и инициировать существующее уведомление об изменениях. До согласования API и авторизации не добавлять имитацию назначения или доверие к данным браузера.

Клиентские `assignedVehicle` и `vehicleAssignment` удаляются при приёме заявки независимо от роли. Клиент не может перезаписать существующий заказ повторной отправкой. Назначение возвращается через текущие приватные `/api/my-orders` и `/api/state`; уже существующие обновления карточек и отметки непросмотренного изменения учитывают смену автомобиля.

## О компании

`fleet.company`: `title`, `intro`, `body`, `partners`. Контакты берутся из существующих настроек сайта. Материалы владельца получены 16.10.2026: архив Untitled.zip, 15 уникальных PDF (ещё 15 — дубликаты). На их основе подготовлены исходные тексты и десять моделей транспорта. Изображения извлечены из PDF без генерации. Они иллюстрируют модели, не гарантируют вид конкретного назначенного автомобиля. Численность автопарка и водителей не опубликована: значения в разных слайдах расходятся. Вместимость УАЗ Patriot оставлена пустой до подтверждения (в презентации указано 10 мест). Багаж и оснащение отдельных моделей не придуманы.

Общие сведения: экскурсионное агентство с 2005 года (7.pdf, 8.pdf), трансферное направление с 2011 года (1.pdf, 2.pdf), расширение сервиса с 2017 года (8.pdf). Основные города выезда — Сухум и Новый Афон (10.pdf). Контакты направлений — 6.pdf, 11.pdf, 14.pdf. Фотографии, модели, места — 4.pdf и 9.pdf.

`Fleet.presentationVehicles()` и `Fleet.companyDefaults()` — начальное наполнение только при отсутствии соответствующего раздела. Явно сохранённые списки (включая пустой), скрытые карточки, пользовательские тексты и данные остальных разделов не заменяются. После открытия редактора начальное наполнение доступно для обычного сохранения; автоматической записи в БД нет. Сервер проверки пожелания и браузер используют одинаковый начальный каталог. Аудит контента продолжает фиксировать только реальные успешные сохранения с именем пользователя.
